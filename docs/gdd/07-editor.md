# 7. Editor

**Status:** partial

The editor is the build half of VibeCity's "build it, drive it, build more" loop. It lives at `/<slug>/edit` (REQ-007) and renders a snap-grid surface where authors place street pieces and buildings. The editor writes through `PUT /api/city/<slug>` (REQ-014, REQ-025) and round-trips with the drive view at `/<slug>` via the Drive CTA in its toolbar (REQ-026).

This file is the canonical spec for the editor requirements (REQ-016 through REQ-027). The first slice lands the snap-grid surface (REQ-016); piece palette, place / rotate / erase, undo / redo, pan / zoom, autosave, and footprint validation each ship as their own slices.

## Snap grid (REQ-016)

The grid is a fixed-size square of cells centered on `(0, 0)`. Each cell maps to one `(row, col)` coordinate in the city schema. v1 ships a `GRID_RADIUS = 8` window (a 17 by 17 visible cell grid) which is enough for a small starter city loop without forcing pan / zoom into this slice.

Coordinates follow VibeRacer's editor convention: row indices grow downward (south), column indices grow rightward (east). Negative rows / cols are legitimate cell coordinates so the grid extends in every direction around the origin.

The grid renders as SVG, sized to `GRID_PIXEL_SIZE = GRID_DIAMETER * CELL_PIXELS` (32 px per cell in v1). The origin cell `(0, 0)` is highlighted so authors have a visual anchor when zero pieces are placed.

The grid is presentational: it consumes a `City` and emits SVG with one `<rect>` per cell. Place / rotate / erase (REQ-020 onward) and pan / zoom (REQ-024) layer onto this surface in their own slices. The `occupiedPieceCells(city)` helper exists today as the constant-time occupancy lookup that REQ-027 (overlap prevention) will use.

The world-space `CELL_SIZE` (in three.js units) used by the future drive-mode scene lives separately. The editor sizes cells for screen comfort without coupling to physics units.

## Piece palette (REQ-017, REQ-018, REQ-019, REQ-058, REQ-060, REQ-061, REQ-062)

Each placed piece renders a small connector glyph (REQ-063) at every cardinal and corner port so authors can read piece orientation and predict whether two adjacent pieces will link before placing the second piece. Cardinal connectors render as a wheat-colored circle at the cell-edge midpoint along the compass direction; corner connectors render as a moccasin-colored circle at the cell corner. Glyphs are non-interactive so they do not steal hover or click events from the underlying cells. Each glyph also carries a `matched` or `open` status against the city's other placed pieces: a port is `matched` when the neighbor cell along its compass direction exposes a port in the opposite direction sourced from a different piece, otherwise the port is `open`. Matched glyphs render with a sage-green stroke and a slightly heavier stroke width so authors can tell at a glance which connectors link and which still need a neighbor; the toolbar surfaces the matched / total counter via a `Connectors matched: M of N` readout that mounts only when the city has at least one connector glyph.

The palette exposes the piece taxonomy from `PieceTypeSchema`. Authors pick a piece, then click the grid to place it (REQ-020). Rotation cycles in 90deg increments via the Rotate button or the `R` keyboard shortcut (REQ-021). The Erase toggle (or the `E` keyboard shortcut) flips the cell-click contract from place to erase (REQ-022); place and erase are mutually exclusive so the next click is always unambiguous. The 4-way `intersection` (REQ-019) is a single-cell piece in the middle of the street palette so streets can branch; it follows the same single-cell footprint pattern as the cardinal basics so no multi-cell footprint plumbing (REQ-059) is required for v1. The mega sweep pair (REQ-058: `megaSweepRight`, `megaSweepLeft`) sits immediately after the single-cell sweep pair so the single-cell to multi-cell sweep block stays contiguous; both entries are 2x2 long-radius turns with a canonical footprint and a rotation handler resolved by `defaultFootprintForPiece` in `snapGrid.ts` (and mirrored locally in `driveScene.ts`) so a placed mega sweep correctly fills four ground quads, rejects overlap on any of its four footprint cells, and erases atomically when any cell is clicked. The `hairpin` (REQ-060) sits immediately after the mega sweep pair as the third multi-cell entry; it covers a 2x3 block (rows -1, 0, 1 across cols 0, 1 at rotation 0) and threads through the same `defaultFootprintForPiece` resolver so a placed hairpin correctly fills six ground quads, rejects overlap on any of its six footprint cells, and erases atomically when any cell is clicked. The corner-connector pieces `arc45` (REQ-061) and `diagonal` (REQ-062) ship as the trailing two single-cell entries per F-007; the editor surface lets builders record placements ahead of the runtime port (sampled centerlines per F-003, wheel contact per F-004, pace notes per F-005, difficulty scoring per F-006, 8-direction connector validation per REQ-063) which lands with the drive scene scaffold (REQ-031).

## Tools

- Place piece (REQ-020): click a cell to place the currently-selected piece type.
- Rotate (REQ-021): 90deg increments.
- Erase (REQ-022): toggle erase mode via the Erase button or the `E` shortcut; click a cell on a piece's footprint to remove the whole piece atomically.
- Undo / redo (REQ-023): immutable history stack ported from VibeRacer's `editorHistory.ts`. Toolbar exposes Undo / Redo buttons (disabled when the respective stack is empty); `Cmd+Z` / `Ctrl+Z` undoes, `Cmd+Shift+Z` / `Ctrl+Shift+Z` and `Cmd+Y` / `Ctrl+Y` redo. Past stack capped at `EDITOR_HISTORY_MAX_PAST = 100`; identity-equality short-circuit in `pushHistory` keeps idempotent setters from polluting the stack with no-op duplicates.
- Pan and zoom (REQ-024): camera controls over the grid. v1 ships the hover preview ghost half of this requirement: hovering a cell renders a translucent overlay that reads place-valid (street brown), place-invalid (warning red on an already-occupied cell), erase-target (warning red on a cell holding content the active palette category would erase), or erase-empty (muted grey on a no-op). Pan and zoom themselves are still deferred.
- Autosave (REQ-025): every accepted mutation writes through `PUT /api/city/<slug>` (REQ-014) after a 600 ms debounce; the editor surfaces `Editing` / `Saving` / `Saved` / `Save failed` status via the `editor-autosave-status` indicator. Builder id cookie is issued on first visit by `src/middleware.ts`. Initial city is loaded via `loadCity(slug)` (REQ-015) so the editor restores a saved city on reload.
- Drive CTA (REQ-026): toolbar button that switches to drive mode at `/<slug>`.
- Overlap prevention (REQ-027): footprint validation rejects placements that would overlap an existing piece's footprint. The editor surfaces post-click feedback for a rejected click via a brief in-grid red flash on the clicked cell so an author who clicks an occupied cell (place mode) or an empty cell (erase mode) sees an immediate signal that the click did nothing. The flash matches the place-invalid preview ghost color so the editor's no-go vocabulary stays consistent across the pre-click forecast and the post-click signal.

## Out of scope for v1

- Multi-select / box-select.
- Copy / paste of subgrids.
- Per-piece metadata (color, decorations).
- Per-author favorites palette.
- Procedural seed cities; v1 always starts with `EMPTY_CITY`.
